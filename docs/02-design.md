# 02. デザイン規則

このサイトの見た目に関する決定をすべてここに集約する。
実装の正典は [mocks/](./mocks/) のHTMLとCSSであり、本ドキュメントはその「なぜ」を記録する。

---

## 1. 設計の原点

**和紙のような白を地とし、wheat を差し色に、焦茶で書く。写実的で、紙の質感を持つ。**

これが唯一の出発点であり、以下のすべてはここから導かれている。

補助的な参照として [nexusadvisors.co.jp](https://nexusadvisors.co.jp/) の構成を見ている。ほぼ無彩色の紙面、明朝の特大見出し、一句だけの細い下線、広いレタースペースの欧文小ラベル、そして「ページをめくる」という本の比喩。この最後の点が、こちらの「一枚の紙」という考えと同じ方向を向いていたため、**§（節）による丁付け**として取り込んだ。

**意図的に違えた点が一つある。写真である。**
参照サイトは写真を一切使わず抽象的な線画で構成している。対象がAIであれば正しい判断だが、こちらの対象は実在する土地である。曇天で彩度の低い現場写真を、加工せず、暗幕もかけずに載せる。これがこのサイトの信用の源泉であり、参照元との決定的な差分になる。

## 2. 色

**wheat 系のみを使う。** 旧デザインの indigo `#4f46e5` / emerald `#10b981` / orange `#f97316` は全廃した。

| トークン | 値 | 用途 |
|---|---|---|
| `--washi` | `#faf8f2` | 和紙の白。ページ全体の地 |
| `--washi-2` | `rgba(224,196,137,.17)` | 二層目の紙。帯セクションのかけ色 |
| `--washi-3` | `#ebe5d6` | 三層目。沈める面（従来のサイクルなど） |
| `--wheat` | `#f5deb3` | 差し色。事業番号、CTAボタン、LinkFarmサイクル |
| `--wheat-deep` | `#e0c489` | wheat の締め。下線、細罫 |
| `--sumi` | `#3d2b1f` | 焦茶。本文、点線、墨の面、ロゴ |
| `--sumi-70 / 50 / 35 / 18 / 10` | `--sumi` のα | 副次テキスト、罫、境界 |

### wheat の扱いに関する制約

**wheat `#f5deb3` は白地に対してコントラストが取れない。** したがって次を禁止する。

- wheat を文字色に使う（背景が焦茶の面を除く）
- wheat の地に白文字を置く
- wheat をCTAボタンの地にして白文字を載せる

wheat が担えるのは**面と線だけ**である。押せるものは原則として焦茶のベタ塗りに `--washi` の文字。

### 帯セクションが不透明色ではない理由

`.section--band` の地色は `--washi-2` という**透過色**である。不透明色にすると、その下に敷いた背景のお皿（後述）を覆い隠してしまうため。同じ理由でフッターの地色も透過色にしている。

## 3. タイポグラフィ

| 役割 | 書体 | ウェイト | CSS変数 |
|---|---|---|---|
| 見出し・大きい数字 | **WDXL Lubrifont JP N** | **400のみ** | `--display` |
| 本文・UI・小さいラベル | **Zen Kaku Gothic New** | 400 / 500 / 700 | `--gothic` |

### ウェイトは400しかない

**WDXL Lubrifont JP N は 400 の一種類しか存在しない。** `--display` を使う要素に 700 や 800 を指定すると、ブラウザが偽ボールドを合成して字面が崩れる。

この書体はもともと太さのある表示用の顔なので、400 のままで見出しとして十分な強さがある。**`--display` を使う新しいクラスを足すときは、必ず `font-weight: 400` を明示すること**（`<b>` や `<strong>` を内側に置く場合も同じ）。

### どこまでが「見出し」か

大きい字は `--display`、小さい字は `--gothic`。境目は次の通り。

| `--display`（WDXL） | `--gothic`（Zen Kaku） |
|---|---|
| `h1`〜`h4`（`.display` `.h2` `.h3` を含む） | `.hashira__no` `.hashira__ja`（柱） |
| `.stat__num` `.stat__fig` `.stat__sub b`（統計の数字） | `.pagehead__no`（§ の丁付け） |
| `.biz__no` `.pagehead__chip`（事業番号） | `.arrow-link__no` `.toc__no` |
| `.toc__ja`（目次の項目名） | `.post__date` `.tl__when` |
| | `.voice__q` `.biz-group__ja` `.cyc__kind` |

`.voice__q`（引用）を本文側に置いているのは、WDXL が表示用の顔で長めの文章の連続には向かないため。

### 配信方法

**フォントはリポジトリに取り込んである。** `public/fonts/` の woff2（486ファイル）を `/fonts/` から配信し、`@font-face` は `src/styles/fonts.css`（`global.css` から `@import`）に置いてある。実行時にもビルド時にも Google へ取りに行かない。

`fonts.css` は外部CSSにまとまるため、**サイト全体で1回だけダウンロードされてキャッシュされる**（brotli後25.7KB）。各ページのHTMLは3.3KBに収まる。

取り込み直すには `make fonts`。詳細と、Astro の Fonts API を使わない理由は [04-web.md](./04-web.md)。

モック（`docs/mocks/`）は素の HTML なので Google Fonts から読んでいる。デザインの確認用であり、配信方針は本番側にのみ適用される。

### 組版規則

- `font-feature-settings: "palt" 1` — 和文の詰め組みを有効にする
- `word-break: auto-phrase` — **見出しには必須**。指定しないと「全／てを知る」「保ち続け／る」のような不自然な位置で折り返す
- 本文 `line-height: 1.95〜2.15` — 和文は欧文より行間を広く取る
- 本文の最大幅 `max-width: 33〜40em`
- 見出しサイズは `clamp()` で流動。`.display` は `clamp(2.15rem, 6vw, 4.4rem)`

### 禁止する組版

- **英字ラベルの ALL CAPS を見出しの直上に置く**（いわゆる eyebrow）。柱と事業ラベルの中だけで使う
- 中黒で連結したメタ情報（`A · B · C`）
- リンク文言の末尾に `→` を文字として書く。矢印は独立した `<span aria-hidden>` として持つ
- `--display` の要素へのウェイト指定（上記の通り 400 しかない）

## 4. レイアウト

### 紙面（`.sheet`）

```
width: min(100% - (--rule-inset * 2 + 56px), 1180px);
```

画面端の点線と衝突しない幅を自動で取る。

### 柱（`.hashira`）

下層ページの各節は、左に**柱**、右に本文という見開き構成（`.spread`）を取る。

```
§ 02          土に触れる事業と、
SERVICES      届け方をつくる事業。
事業内容
              ……
```

柱は `position: sticky` でスクロールに追従する。印刷物の柱（ページ上部の見出し）と同じ役割で、いま紙面のどこを読んでいるかを常に示す。1040px 未満では通常のブロックに戻る。

### 左揃え

**全ページで左揃えを基本とする。** 旧デザインは全セクションが中央揃えだったが、中央揃えはLPの定型であり、読み物としては視線の起点が定まらない。

## 5. 構造装置

装置は飾りではなく情報を担う。以下の5つ以外を足さない。

### 画面端の焦茶点線（`.edge-rule`）

このデザインの背骨。画面の左右端から `clamp(14px, 3.2vw, 44px)` の位置に、**3px の点を29pxピッチ**で縦に通す。`position: fixed` なのでスクロールしても動かず、ページ全体が一枚の紙として繋がって見える。

### 背景のお皿（`.plates` / `mock.js`）

丸・ひし形・六角の3種を、**縁のある皿**に見えるよう外周と見込み（内側の輪）の二重線で描く。3×3の粗いグリッドの各マスを35%の確率で空け、残りに種類・大きさ・位置をランダムに配置する。ページを開くたびに配置が変わる。

焦茶12%・線幅1.6px。**最下層（`z-index: -1`）に敷く**。この重ね順は必須で、セクション側に `z-index` を与えると背景色ごとお皿を覆い隠す。

### 本文の下のベール（`body::before`）

背景のお皿の上に本文が乗ると読みにくいので、紙面の下に薄いベール（`--color-veil` = `rgba(247, 246, 241, .78)`）を1枚敷いてお皿を弱める。

**カードではない。** 端を `filter: blur(22px)` でぼかして消すので輪郭が出ず、「一枚の紙」という構成を壊さない。ぼかしで端が薄くなる分、紙面より広め（`--sheet + 120px`）に取っている。画面端ではベールが切れるため、お皿が濃いまま残り、結果としてゆるい周辺減光になる。

`main` ではなく `body` に置いているのは、**フッターまで含めてページ全体を覆うため**。`main` だけだと footer との境目で背景の濃さに段差が出る。

お皿は焦茶12%だが、ベールの下で実質2〜3%まで落ちる。線が消えるのではなく「見えるが本文を邪魔しない」濃さになる。

### 右余白の縦組み（`.tategaki`）

`writing-mode: vertical-rl` による和文の縦組み。参照サイトは回転させた欧文を置いているが、こちらは日本語組版として成立する形を選んだ。1340px 未満では非表示。

### 記事の版面幅（`--measure`）

活動日誌の記事では、**本文の1行の幅と見出し写真の幅を完全に揃える**。両方 `--measure`（`44rem` = 704px）を参照し、定義元はこの1箇所だけ。

`em` ではなく `rem` なのは、`.prose` の `font-size` が `.95rem` のため、`em` だと本文と写真で基準がずれて数値を揃えても一致しないから。

日本語の1行は約46文字になる。40〜46文字は和文として読みやすい範囲に収まっている。

記事の扉（`.pagehead`）の直下に写真を置くので、本文セクションの上パディングは `0` にしている（`.postbody`）。両方効かせると最大252pxの空白ができる。

### 写真プレート（`.plate`）

**写真は台紙に貼った印画紙として扱う。** 13px の余白を残して `--washi` の地に載せ、下にキャプションを置く。文字を写真に重ねない。

これがこのデザインで唯一「大胆さ」を使っている場所である。曇天で彩度の低い写真に暗幕をかけずに済み、写実のまま出せる。

### 日付の焼き込み（`.plate__date`）

事業紹介の写真には、右下にチェキ風の日付を載せる。フィルムの日付写し込みは琥珀色であり、**`--wheat` とほぼ同じ温度帯にあるため、パレットを崩さずに再現できる**。`tabular-nums` で桁を揃え、暗い写真の上でも読めるよう影を敷く。

図版を `object-fit: contain` で収める面（`.plate--fit`）は地が明るく琥珀が沈むため、`--sumi-70` に切り替える。

| 事業 | 写真 | 日付 |
|---|---|---|
| 01 体験型学習 | `hero-03.jpg` | 2026/05/01 |
| 02 提携農家連携 | `hero-01.jpg` | 2026/09/05 |
| 03 Web制作 | NARATIVE様 制作支援 | 2026/08/01 |

日付は装飾なので `aria-hidden="true"`。日付そのものを情報として伝える必要がある場合は、キャプション側に書く。

### wheat のマーカー（`.ul`）

見出しの一句だけに引く。**文字の下から30%に重ねる**：背景として敷くので文字は線の上に残り、可読性は落ちない。

```css
.ul {
  background-image: linear-gradient(var(--wheat), var(--wheat));
  background-size: 100% 30%;
  background-position: 0 100%;
  background-repeat: no-repeat;
  box-decoration-break: clone;  /* 行をまたいだとき両端を正しく描く */
}
```

`background-size` の高さ 30% は**インライン要素の内容領域**（おおむね font-size 相当）に対する割合なので、見出しの大きさが `clamp()` で変わっても重なり量の比率は保たれる。

暗い面（`.ink`）では wheat のベタが白文字を潰すため、`rgba(245, 222, 179, .42)` に透過させて重ねる。

> 当初は文字に重ならない細い下線（`box-shadow: inset 0 -.14em 0`）だったが、差し色としての存在感が足りないため重ねる方式に変更した。全面を塗りつぶすマーカーは、暗い面で黒塗りに見えるので使わない。30%という量は、文字を邪魔せずに線が見える境目にある。

### 使わないもの

- 角丸カードの並列（`rounded-3xl` + `shadow` の量産）
- グラデーション背景、ぼかした装飾円、オーロラ
- グラスモーフィズム
- 内容が順序でないところへの 01 / 02 / 03 の付与（サイクル比較とスケジュールは本当に順序なので可）

## 6. 写真

### 現在の素材

| ファイル | 内容 | 用途 |
|---|---|---|
| `src/assets/hero/hero-01.jpg` | 活動を説明している場面 | 事業02、お問い合わせ |
| `src/assets/hero/hero-02.jpg` | 草を刈り整えた耕作地と里山の集落 | トップ表紙、事業詳細の扉 |
| `src/assets/hero/hero-03.jpg` | 川と杉山 | 事業01 |

### EXIF 回転への対応（対応済み）

`hero-02.jpg` は EXIF orientation=3（180°）、`hero-03.jpg` は=6（90°）を持っており、生のピクセルは回転前の向きで保存されていた。ブラウザは EXIF を尊重するのでモックでは正しく見えていたが、ビルド時の最適化で崩れる危険があったため、**向きを焼き込み、長辺2400pxへ縮小して置き換え済み**。

| ファイル | 対応前 | 対応後 |
|---|---|---|
| `hero-02.jpg` | 4000×3000 / orientation=3 / 5.7MB | 2400×1800 / EXIF なし / 1.2MB |
| `hero-03.jpg` | 4000×3000 / orientation=6 / 3.5MB | 1800×2400 / EXIF なし / 522KB |

新しい写真を追加するときも同じ正規化を通すこと。手順は [04-web.md](./04-web.md)。

### ヒーローのカルーセル化（将来の検討事項）

> **現時点では単一の写真プレートで表示している。**
> 今後、現場写真が増えてきた段階で、**ヒーローをカルーセル形式にすることを検討している。**
>
> 検討時に守るべき制約：
> - 自動再生はしない。モーションの方針（次節）に反する
> - 写真に文字を重ねない。プレートの構造は維持する
> - `prefers-reduced-motion: reduce` で切り替えアニメーションを無効化する
> - キャプションは写真ごとに切り替える。撮影地と時期は写真の一部として扱う
> - JavaScript が無効でも1枚目が表示されること

## 7. モーション

**非操作起因のモーションは、ページ全体で1箇所だけ。**

旧デザインにあった全セクションのスクロール連動フェードイン（`.scroll-reveal`）は全廃した。各セクションが順に浮かび上がる演出は生成物の定型であり、読み物のリズムを壊す。

`prefers-reduced-motion: reduce` では、すべての `animation` と `transition` を無効化し、`scroll-behavior` も `auto` に戻す。

ホバー時の遷移（0.18〜0.25秒）は、操作への応答なので許容する。

## 8. アクセシビリティ

- `a:focus-visible` / `button:focus-visible` に `outline: 2px solid var(--sumi)` を明示する
- 現在のページは `aria-current="page"` で示す。色だけでなく下線を併用する
- 装飾要素（点線・お皿・縦組み・矢印）はすべて `aria-hidden="true"`
- ロゴは `<img>` の `alt="LinkFarm Tech."` で社名を伝える
- 本文の文字色 `--sumi` `#3d2b1f` は `--washi` `#faf8f2` に対して十分なコントラスト比を持つ。`--sumi-50` 以下は補助情報にのみ使い、本文には使わない

## 9. ロゴ

`src/assets/linkfarm-logo-yoko.png`（411×75、単色 `#1b003d`、透過PNG）が正のアセット。**このファイルには手を加えない。**

## 10. CSS 実装上の注意

### 詳細度の衝突

この設計では**同じ詳細度のルールが色を奪い合う事故**が繰り返し起きた。実装時に必ず確認すること。

| 事故 | 原因 | 対処 |
|---|---|---|
| ヘッダーの「お問い合わせ」から文字が消えた | `.nav a`（0,1,1）が `.btn--fill`（0,1,0）に勝つ | `.nav a.btn--fill { color: var(--washi) }` |
| 現在地のページでボタンの文字が消えた | `.nav a[aria-current]` と `.nav a.btn--fill` が同点で後勝ち | `.nav a.btn--fill[aria-current="page"]` |
| 記事タイトルが素のリンク色になった | セレクタが `.post h3 a` のまま、マークアップは `h2` | `.post :is(h2, h3) a` |

### 重ね順

```
z-index  60   紙のグレイン（body::after, mix-blend-mode: multiply）
z-index  50   ヘッダー
z-index  40   画面端の点線
z-index  39   右余白の縦組み
z-index   0   本文・セクション・フッター（z-index を与えない）
z-index  -1   本文の下のベール（body::before）
z-index  -2   背景のお皿（.plates）
```

**セクションに `z-index` を与えてはいけない。** 与えると背景色ごとベールとお皿より上に来て覆い隠す。

**ベールとお皿の z-index は必ず明示する。** どちらも負の値で同じ階層に置くと、ツリー順で `.plates`（body の実子）が `body::before`（疑似要素＝先頭扱い）より後に描画され、**お皿がベールの上に乗ってしまう**。
