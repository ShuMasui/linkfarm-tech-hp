# ブログ記事の枠を作る

本文は書き手が書く。このスキルが受け持つのは**枠**だけ。
枠を外すと URL が変わったりビルドが落ちたりするので、ここだけは規約どおりにする。

## 1. ファイルを置く

`src/content/blog/YYYYMMDD_<英小文字とハイフン>.md`

- 日付は公開予定日。`pubDate` と揃える
- `.mdx` にするのは、本文中で Astro コンポーネントを使うときだけ。通常は `.md`

## 2. frontmatter を書く

```yaml
---
title: "記事のタイトル"
description: "一覧と OGP に出る説明文。1〜2文で内容が分かるように書く"
pubDate: "YYYY-MM-DD"
heroImage: "../../assets/blogshero/<画像ファイル名>"
slug: "url-になる文字列"
tags: "タグ1, タグ2, タグ3"
---
```

**`slug` は URL そのもの。** `/blog/<slug>/` として公開される。

- **書き忘れるとファイル名がそのまま URL になる。** 必ず書く
- **既存記事の `slug` は変えない。** 公開済み URL が死ぬ
- 英小文字とハイフンのみ

**`tags` はカンマ区切りの「1本の文字列」。** 配列ではない。
`src/content.config.ts` の zod スキーマ側で split されるので、`["a", "b"]` と書くと壊れる。

`heroImage` は `src/assets/blogshero/` への**相対パス**。
`image()` 型なので、**実ファイルが無いとビルドが落ちる**。先に画像を置く。

検証している定義は `src/content.config.ts` にある。迷ったらそれが正。

## 3. hero 画像を置く

`src/assets/blogshero/` に置く。記事ファイルと同じ日付プレフィックスにすると対応が追いやすい。

既存ファイルは `.png` と `.jpg` が混在し、区切りも `-` と `_` が混ざっている。
**揃っていないのは既存の事情なので、新しく足すぶんは記事ファイル名に合わせる。**

## 4. 通す

```
make check
```

frontmatter の型と画像の実在はここで落ちる。通ってから PR に進む。

## 固有名詞

社名の表記ゆれに注意する。正しくは **株式会社ウエルアップ**（「ウェルアップ」ではない）。
