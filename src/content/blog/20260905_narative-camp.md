## 向き合った課題：サムズアップ農園さんが抱える「農地監視システムの高機能・高価格問題」

今回のCAMPのお題は、**「宇陀が抱える問題なら何でも良い」** という非常に自由度の高いものでした。

そこで私たちLinkFarm Tech.は、日頃から深く関わらせていただいている **サムズアップ農園様** が実際に直面していた、**「農地監視システムの高機能・高価問題」** にアプローチすることに決めました。

### 農業の根本課題：「見に行かないといけないが、行けない」ジレンマ

この問題の根底には、**「農業をする人は、作物の様子や天候、獣害、水管理のために必ず農地を見に行かなければならない」** という農業特有の根本的タスクが存在します。

しかし、多くの場合、農地は都市部や自宅から離れた場所にあります。
- 毎日往復して見に行くだけでも相当な重労働になる。
- 大雨や台風などの荒天時は、危険で見に行けないのに「水路は溢れていないか」「畑は無事か」と気をもみ続けることになる。

まさに、**「見に行かなければいけないけれど、見に行けない／見に行くのがものすごくしんどい」** という切実なジレンマを抱えているのです。

### 既存の「農地監視カメラ」が抱えるハードル

この痛みを解消するため、大手IT・農業資材メーカーからは「農地監視システム（監視カメラ等）」が提供されています。

しかし、現場の農家様にお話を伺うと、そこには大きなギャップがありました。
1. **高機能ゆえに非常に高価**：確かに国の補助金を活用すれば初期購入自体はできるケースもありますが、導入の敷居は依然として高いです。
2. **高額な保守運用費と不要な機能**：毎月のクラウド利用料や保守費用が高く、使わない高度な機能のためにお金を払い続けることへの心理的ストレスが大きい。
3. **敷設・設置の手間**：大掛かりな電源工事やネットワーク工事が必要で、導入までに多くの時間と労力がかかる。

「農家の見回り負荷を減らす監視システムは絶対に必要。しかし、既存の製品は現場の農家の方々に真に刺さっていない」——これが私たちの見出したリアルな課題でした。

## 私たちの仮説と合宿のゴール

そこで私たちは、次のような仮説を立てました。

> **「高機能・高価格という現状のアプローチよりも、現場に本当に必要な最小限の機能に絞り、その価値にだけ対価を払うモデルの方が、農家様には深く刺さるのではないか？」**

そして今回のNARATIVE CAMPのゴールを、**「この仮説を検証するための実証機材・システム（MVP）を2泊3日で創り切ること」** に定めました！

## 開発したシステム：『EdgeWatcher』

こうして誕生したのが、農地見守りシステム **『EdgeWatcher（エッジウォッチャー）』** です。

仮説を検証するため、デバイスとシステムには以下の明確な要件とコンセプトを設定しました。

| 既存システムの課題 | EdgeWatcherのアプローチ | 実装したコンセプト |
| :--- | :--- | :--- |
| **高価な専用監視カメラ** | **休眠スマートフォンで代替** | 農家様の引き出しに眠る古いスマホをエッジカメラとして再利用。ハードウェア費用を実質ゼロに。 |
| **敷設・設定に時間がかかる** | **QRコード読み取りで即時利用開始** | Webアプリにログイン後、スマホにアプリを入れてQRを読み取るだけでペアリング完了。 |
| **不要な高機能・高額保守** | **画像単体表示に絞ったMVP** | 常時ストリーミングや過剰なAI解析を省き、「定期撮影された画像を確認できる」最小限の機能に特化。 |

## システムアーキテクチャ：長期運用を見据えたAWS完全サーバーレス設計

EdgeWatcherは、合宿期間中の一発モノで終わらせず、**「長期的にポートフォリオとして低コストでWeb上に常時公開し続けられること」** を前提として設計しました。そのため、アイドルコストがゼロに近い **AWS完全サーバーレス構成** を採用しています。

![EdgeWatcher AWSサーバーレスシステムアーキテクチャ](../../assets/blogs/20260905_narative_camp/aws-architecture.png)

### アーキテクチャのこだわりポイント

1. **API Gateway（HTTP API）＋ AWS Lambda によるコスト削減とシンプル化**
   - Webアプリとスマートフォンの双方からのAPIリクエストを API Gateway に集約。
   - REST API ではなく **HTTP API** を選択することで、通信コストとレイテンシを大幅に削減しました。
   - MVPとして重たい処理はあえて作らず、シンプルなデータ処理に徹して Lambda に集約しています。

2. **フロントエンドの静的配信とCognitoによるアクセス制限**
   - Web管理画面はSPA（Single Page Application）としてビルドし、CloudFront ＋ S3 でホスティング。
   - 管理画面は **Amazon Cognito** を用いてアクセス制限をかけ、セキュアな環境を担保しています。

3. **Lambda Authorizer ＋ DynamoDB による柔軟な端末認証**
   - スマートフォンアプリ側の認証についても当初はCognitoを利用する案がありました。
   - しかし、「紛失時や停止時にセッションを即座に無効化したい」「端末のライフサイクル（登録・破棄）がWeb管理画面側に完全に依存している」という要件がありました。
   - そこで、**セッションコードの発行からアップロードシークレットの生成、API呼び出し時の認証認可までをすべて Lambda Authorizer でハンドリング** する構成に決定。その高速な保存先・ステート管理として **Amazon DynamoDB** を採用しました。

## 怒涛の2泊3日！開発タイムライン

限られた時間の中で、調査からインフラ構築、実装、テスト、発表までを完遂させるため、以下の過密スケジュールで進めました。

### 開発秘話：コーディング遅延を「AIエージェントのフル活用」で突破！

実は2日目の夜から3日目の朝にかけて、API連携や認証周りの実装で想定以上の難所にぶつかり、**コーディングの進捗が大幅に遅れるという危機的な状況** に陥りました。

通常の開発であればここでスコープを削るところですが、今回は **最新のAIエージェントを最大限に活用**。あたかもチーム内に複数人の優秀なエンジニアを即座に増員したかのように、インフラ検証、テストコード作成、UI実装を並行して推進しました。その結果、合宿終了の数時間前には完全なE2E動作テストをパスし、無事に動くプロダクトとしてリリースまでこぎつけることができました！
